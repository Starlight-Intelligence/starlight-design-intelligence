## Provider rehearsal, in order

1. Select an explicitly connected Stripe sandbox/test context. No live credential, object or transaction may substitute. Install test credentials in the approved secret manager, never chat or source.
2. Create/bind the test product and price for Essential, seller-approved terms version and immutable artifact digest. Use a server-issued purchase-attempt identity, not a caller-supplied amount or product path.
3. Complete one real provider sandbox checkout. Capture provider IDs and test-mode evidence without logging secrets or payment details. Retrieval must confirm paid status, exact line item, currency, amount, buyer binding and artifact/version metadata.
4. Deliver through the signed webhook path even when the success redirect is never opened. Replay the same event, a second event for the same order and concurrent callbacks; one durable entitlement must result.
5. Authenticate the buyer through the existing storefront, stream private bytes or issue an appropriately scoped short-lived grant, verify ZIP hash, then test another buyer, forged/expired grant, changed file/hash and revoked/refunded order. None may obtain the artifact.
6. Restart the approved backend and retry. Refund/revocation must survive restart and late payment-event replay. Record the selected policy for partial refunds.

Current account discovery on 13 November exposes only the live FrankX context through both Stripe connections, and the execution environment has no Stripe test key or webhook secret. The real-provider gate is therefore blocked. No sandbox purchase is claimed until a test context is connected and the receipt above exists. Existing storefront delivery repair PR #1075 is the dependency; the dedicated sandbox follow-up must stay draft and leave live routes closed.
