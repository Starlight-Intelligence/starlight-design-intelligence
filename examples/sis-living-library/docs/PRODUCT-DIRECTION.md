# Living Design product family / RC 0.2

Recipient: an AI product builder who needs a deployable interface foundation with explicit operational state. Job: install, customize and deploy without any Starlight service. Primary action: inspect a working experience, then install the local package. Signature: evidence and permission scope remain adjacent to the proposed action.

Three composition directions were compared:

| Direction | Composition | Type and material | Decision |
|---|---|---|---|
| Data terminal | Narrow rail, mission table, adjacent evidence and decision | Instrument Sans, tabular Plex figures, opaque reading panels, one selection line | Selected for the three workspaces; dense enough to inspect a whole decision |
| Black plane | One dark plane, inversion-led actions, almost no panel chrome | Same brand type, tonal elevation | Declined: weak separation of evidence from control scope |
| Porcelain folio | Reading-first full-width documents, editorial headings, side notes | Daylight and Instrument Serif, sparse rules | Retained as the light theme and launch editorial treatment, not the operator default |

Glass is a bounded contextual material: the launch specimen and optional translucent navigation. Sustained reading remains opaque. This intentionally overrides the imported diagnostic's blanket glass ban because glass is an explicit product requirement. Existing --sl-* themes and core APIs are preserved. No portfolio identity is promoted.

The console answers which proposed handoff needs a decision; StarBrowser answers what the comparison can read and where its evidence came from; the investor workspace answers what supports a thesis; the launch page answers exactly what source each target product includes. All demo data is synthetic, and all operations stay local.

Motion is limited to existing press, focus, disclosure and progress feedback. New compositions have no continuous or entrance animation. Reduced motion resolves to the same information immediately. The specimen's orbit is still geometry, never a live agent or progress signal.

Canonical source remains this repository's existing Living Library. packages/materials retains its separate GPU glass scope. The existing FrankX product catalogue owns commerce; Living Glass is proposed as an evolution of its Aurora UI Kit SKU, with the other kits staged behind the current checkout gate.
