## FrankX article draft

**SEO title:** Designing agent dashboards with approvals, evidence and cost limits

**Slug:** designing-agent-dashboards-approvals-evidence-cost

**Meta:** A practical React starter showing mission scope, approvals, evidence and token budgets, with portable source and explicit integration boundaries.

An agent dashboard earns its space when it helps you make a decision. Show the proposed action, the exact scope and the evidence before the approval button. Put costs next to the mission that incurs them. Keep cancelled work visibly cancelled.

The Starlight candidate makes that loop inspectable with local data. Approve the research mission, start its simulation, then advance one step at a time. Replay the same command key and usage stays unchanged. Choose the budget-boundary mission and the next oversized step stops before it adds tokens or cost. Export the event receipt to inspect what happened.

That is a useful interface contract. A production adapter still has to authenticate the caller, bind approvals to immutable inputs, enforce budgets server-side, and commit idempotent execution records. The demo labels that boundary instead of disguising a simulated workflow as a connected agent fleet.

Glass Core is the underlying React system. Opaque reading planes do most of the work; optional glass separates navigation and context. Typed component contracts expose installation, constraints and dependency metadata to coding agents. The package and independent Next.js consumer keep the implementation portable.

This remains a release candidate. Current browser verification, final license terms and sandbox fulfillment are release gates. Inspect the source and working demonstration before evaluating a purchase. No performance result, customer result or commercial availability is implied by this draft.
