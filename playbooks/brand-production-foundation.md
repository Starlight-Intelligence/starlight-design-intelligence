# Portfolio design production system

## Authority
Use agentic-ops/registry for brand and repository identity; Starlight-Intelligence/starlight-design-intelligence for shared design protocol and owning brand packs; each product repository for deployed tokens/components. Figma is a native design projection, Canva a campaign production projection, Drive a working-source/review location. This bundle is a review handoff, not a new canonical repository or registry.

## One release per brand
Freeze one source revision and surface mode. Inventory current master assets before creating replacements. Distinguish existing, candidate, selected, approved and published. Import exact approved marks; never ask a generator to redraw them. Preserve rejected work in exploration, never in release folders.

Figma structure per brand: 00 Start here; 01 Foundations; 02 Identity; 03 Components; 04 Flows; 90 Exploration; 99 Archive. Use semantic variables aliased to primitives, declared scopes and CSS syntax. Keep components outside application frames, use instances, expose text/state/icon properties, and map native IDs to actual code exports. Publish a library only after a real desktop/phone flow and independent review. Use one writer per file; preserve IDs on update.

Canva structure inside each existing brand folder: 00 Read me; 01 Identity masters; 02 Locked templates; 03 Campaigns/YYYY-MM; 04 Approved exports; 99 Archive. Separate editorial, product and event templates. Lock logo position, safe margins, footer/source label and type roles in the editor. Brand Kit setup uses approved files and exact font roles; kit editing/publishing and lock management are not exposed by the connected tools in this session. The current empty Brand Kit listing is an account observation, not proof that historical kits never existed. Editable imported designs are not automatically locked Brand Templates.

## Production sequence
1. Resolve source pack, customer job, destination and one acceptance artifact.
2. Inspect existing flow and references. Record what works, conflicts and missing evidence.
3. Write exact copy. Draw three materially different directions only for a new identity or flagship composition.
4. Select a draft direction for review; build with tokens, editable vectors and reusable components.
5. Review at 375 and 1440 widths plus real destination size. Inspect wrapping, contrast, counter shapes, hit targets, factual claims, rights and crop safety.
6. Produce the channel derivative and caption from the same campaign ID. No new promise or price in a derivative.
7. Obtain the required identity/public release review; export immutable files and record placement.
8. For websites, implement in the owning repo, run existing checks, compare browser evidence, then record the actual deployed revision. For social, leave as draft until destination and publication authority are explicit.

## Skill routing
Brand direction: rockstar-brands:brand-director → focused brand-identity/brand-voice/brand-review. Figma library: figma-use + figma-generate-library; views also use figma-generate-design. Logo work: logo-system and vector editing; icons: product-approved family, exact upstream source/version/license. Web implementation: owning product TASTE/DESIGN + world-class-web-release, typography-art-direction and starlight-design-review. Content: frankx-social-studio or brand-content; animations only when the story needs motion-design. Raster illustration: imagegen after canon/reference retrieval and generated-asset gate. These are routing recommendations, not claims that every skill is installed in every host.

## Review receipt
Required fields: brand_id, campaign_id, customer_job, source_repository, source_commit, pack_hash, surface_mode, native_file/node/design IDs, asset IDs/version/hash, owner, rights_state, review_state, placements, checks_run, checks_pending, reviewer, approval and rollback. Unknowns stay null. Store private provider IDs outside public source repositories.

## Quality bar
Recognizable silhouette and typography; one subject per frame; purposeful asymmetry; text before decoration; no fabricated traction, testimonials or metrics; no generic neon AI stock; no generated UI text or third-party marks as factual evidence. Self-review cannot substitute for independent acceptance. Measure first-value completion, time to produce an accepted artifact, corrections per release, stale asset placements and reuse; begin with unknown baselines.

## Maintenance
Weekly: review the next two weeks of content and broken placements. Monthly: inspect one real product flow per active brand and retire superseded assets by reference. Every release: regenerate derivatives from pinned source. Dedicated chats hold working context; the versioned pack and receipt carry decisions between chats.
